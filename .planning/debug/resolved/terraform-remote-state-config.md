## Resolution

root_cause: "The regenerated remote.proto changed TerraformRemoteState.config from map<string,string> to google.protobuf.Value, but both of its users in the drivers still treated it as a map. terraform.pinc remote() assigned a dict, which is the compile error. github_actions.pinc _remote_state_id called config.get(...), which fails with 'field get not found in message google.protobuf.Value' once the writer is fixed."
fix: "terraform.pinc: load Struct/Value from struct.proto and wrap config_for(...) in Value(struct_value=Struct(fields={k: Value(string_value=v)})). github_actions.pinc: build the settings dict from config.struct_value.fields[k].string_value. Generated protos untouched."
oracle_type: specified (handshake_test deps assertion + make gates messages + original compile error)
verification: "Reproduction: `command make -C test` exits 0 with zero error lines in the log (checked by grep, because protoconf compile exits 0 even on error); mod tidy, compile, workflows, and 'gates: both compile gates fired' all pass. handshake_test's cross-state edge assertion passes. examples/otel-demo mod tidy + compile has zero error lines. Revert checks: undoing the writer brings back the original error verbatim, and undoing the reader gives 'field get not found in message google.protobuf.Value'. A probe shows config written as a plain JSON object. guardrail_verdict: accepted"
