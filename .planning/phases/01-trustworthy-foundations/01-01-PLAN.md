Workflow name: `drift`.

Triggers (D-03) — source paths, never `test/outputs/**`. The generated pipeline already
filters on `test/outputs/core_test/**`, which by construction cannot fire for a source edit
with no regenerated output, which is the exact failure being guarded against:
`pull_request` with
`paths: [test/src/**, src/**, drivers/**, test/CONFIGSPACE, test/protoconf.lock, .github/workflows/terraform.yaml]`;
`push` with `branches: [main]` and the same `paths`; `workflow_dispatch: {}`.
The last entry is not a source tree and is deliberate: `.github/workflows/terraform.yaml` is one
of the three trees the assertion covers, and this file's own prohibitions say it is never
hand-edited. Without it in the filter, a PR that ONLY hand-edits the generated workflow matches
no trigger, drift never runs, and the edit lands green — the guard would be blind to tampering
with the very artifact it exists to protect. D-03 fixes the SOURCE trigger list; adding the
asserted artifact alongside it is within the discretion CONTEXT grants over "exact workflow YAML
structure" and contradicts nothing D-03 says.
Use only these three trigger keys. Do NOT use the privileged fork-context variant of the
pull-request event — this job runs contributor-authored Starlark through a compiler, so it
must never hold a write-scoped token.

Top-level `permissions:` block containing exactly one entry, `contents: read`. Nothing else.
No OIDC token grant, no pull-request write. This job authenticates to nothing: every
`remote_repo` in `test/CONFIGSPACE` is a local relative path, so the build is hermetic and
offline apart from the one pinned download below.

One job, `compile`, `runs-on: ubuntu-latest`, with job-level `env:`
`PROTOCONF_VERSION: 0.2.0-rc2` and
`PROTOCONF_SHA256: eeb8415960567e23f1a3a4acb8eb28a07cb68a544c4c2e3fd41fb7ebdfde9f3a`.

Steps, in this order:

1. `uses: actions/checkout@v4` — matching the pin the generated pipeline already uses at
   `drivers/cicd/github_actions/src/github_actions.pinc:387`.

2. `name: install protoconf`, a `run:` block that curls
   `https://github.com/protoconf/protoconf/releases/download/v${PROTOCONF_VERSION}/protoconf_${PROTOCONF_VERSION}_linux_amd64.tar.gz`
   to `/tmp/protoconf.tar.gz` with `curl -fsSL`, verifies it by piping
   `"${PROTOCONF_SHA256}  /tmp/protoconf.tar.gz"` into `sha256sum -c -`, extracts with
   `sudo tar -xzf /tmp/protoconf.tar.gz -C /usr/local/bin protoconf` (the tarball has no
   nested directory — the binary is at its root), and ends with `protoconf --version`.
   The checksum above is the publisher's own value from the `v0.2.0-rc2` `checksums.txt`,
   confirmed by RESEARCH.md against an artifact actually downloaded. D-04 forbids `latest`.

3. `name: drop the machine-local lock`, `run: rm -f test/protoconf.lock`. This line is
   mandatory and the workflow is broken without it. `test/protoconf.lock` commits an
   absolute `file:///Users/smintz/git/platform-engineering/...` `getterUrl` per dependency;
   on a runner that path does not exist, `protoconf mod tidy` fails rather than falling back
   to the relative `url` in `CONFIGSPACE`, and `protoconf compile` then fails on an empty
   cache. Deleting the lock makes tidy re-resolve against the runner's own checkout.
   Carry a comment above the step saying so — RESEARCH.md §Pitfall 1 has the pasted failure.

4. `name: rebuild`, `run: cd test && make test`. This is the repo's real build (D-02); the
   drift check is that build plus an assertion. Do not substitute `protoconf mod sync` or a
   bare `protoconf compile`.

5. `name: assert generated output is current`, a `run:` block that first runs
   `git add -A -- test/materialized_config test/outputs .github/workflows/terraform.yaml`

   block that echoes
   `::error::generated output is stale. Run 'cd test && make test' and commit the result.`
   and exits 1. The staging step is mandatory: `git diff` compares the index to the worktree
   for tracked paths only, so a change that adds a new component — and therefore a new,

   so. `test/protoconf.lock` is deliberately absent from these three paths: CI regenerates
   it, and even locally the release binary and the developer's build disagree about JSON
   whitespace in it (RESEARCH.md §Pitfall 2).

Do not add a terraform install step. Do not add any secret, repository variable, or
credential step.

| repository -> public git history | Everything committed here is world-readable on a public repo. |
