<objective>
Close FOUND-04 and FOUND-05: make two classes of silently-wrong Terraform wiring into compile
errors that name the fix, and fix the one live instance of the first class.

Purpose: the platform's cross-state wiring has to be trustworthy before four new drivers are
built on it. Today a component can be given a local backend and CI will apply it on a runner
whose disk is thrown away — which is not a smaller choice, it is a state that never persists,
so every apply plans against nothing and recreates everything. Redis is the live instance of
exactly that bug. And today a cross-state read pointing at a state this pipeline does not
write yields no ordering edge, so the pipeline is free to apply the reader before the writer;
the resulting order is not wrong by a little, it is arbitrary. FOUND-05 is the guard that
makes the near/far handshake convention enforceable for the database and mesh drivers in
Phases 3 through 5.

Output: three module-private functions in the CI driver, one changed argument at a call site,
one probe, and exactly two changed golden files.
</objective>

compile-time Starlark system with no runtime, and are recorded in `must_haves.stated_assumptions`:

- **FOUND-04 / FOUND-05, encoding.** State ids are NOT driver-owned text: `_backend_state_id`
  and `_remote_state_id` interpolate `bucket`, `key`, `region`, `organization` and `workspaces`
  from the call site, and `key_for` receives the component author's `domain` and `name`. The
  category still does not apply, for a different reason than "no user input": both sides of
  every comparison derive from the same call-site strings, and they are compared with Starlark
  string equality. Any normalization or encoding divergence between the two sides yields
  inequality, and inequality is precisely the condition `_check_reads_are_produced` fails on —
  the design fails closed into the FOUND-05 error rather than silently accepting a near-match.
  A normalization rule would therefore govern nothing that failing closed does not already
  cover. Recorded here so a later phase does not build on the false premise that these strings
  contain no author-supplied text.
- **FOUND-04 / FOUND-05, concurrency.** `protoconf compile` is single-process and single-pass,
  with no parallelism and no interruption semantics, and both checks are pure. A failed compile
  writes no materialized file at all, so there is no partial state to guarantee anything about.
