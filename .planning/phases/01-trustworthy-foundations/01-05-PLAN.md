<objective>
Close FOUND-03 (ROADMAP SC-2). `SelectComponents` is exported, reachable and wired, and it
returns an incomplete answer on the one graph shape it was written to handle.

Purpose: `Component` builds each dependency factory once per parent, so a diamond is a tree
holding two DISTINCT objects with equal content. `found[c] = True` keys a dict by proto VALUE,
which collapses them, so the caller receives exactly one of the two live objects — chosen by
first-insertion-wins ordering in `walk_upstreams`. 01-VERIFICATION.md proved it live: a
`top -> {mid1, mid2} -> leaf` diamond returned 1 leaf; mutating that leaf left `mid2`'s leaf at
`""`; re-selecting after the mutation returned 2, because the two objects no longer had equal
content. The function is neither complete nor idempotent, and applying a hook across a selection
is exactly what Phase 5 SEC-01 and Phase 2 COST-01 are planned to do.

Output: a selector that returns every occurrence, and a fixture that would have caught this —
one that mutates through the selection and reads the result back through a walk of its own.
</objective>

real rather than prose noise: this plan changes what the selector treats as one thing.

- **Primary noun:** a **component occurrence** — a live object reached at a position in the
  dependency graph. Not "a component" identified by its content.
- **Decision: `promote`.** The occurrence becomes the thing `SelectComponents` returns, and
  value-equality is demoted from an identity rule to what it actually is: an implementation

What 01-VERIFICATION.md measured, by running it rather than reading it. On a diamond

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| platform author's predicate → the graph traversal | An author-supplied function decides which components a cross-cutting hook touches. Its blast radius is every component in the subtree. |
| `SelectComponents`' returned list → the caller's mutation | The returned objects are live references into the graph. A mutation through one of them is the mechanism SEC-01 and COST-01 are built on; an object the list omits is a component the hook never reaches. |
| the returned set → SEC-03's generated audit artifact | A security engineer reads the artifact to learn which components a policy applied to. |
