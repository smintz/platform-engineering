in this plan's `gate_matrix` verbatim — every one was measured against this checkout, and the

**Shape.** One target, one recipe, written as a single backslash-continued shell invocation so
that one `trap ... EXIT` covers every exit path. Make runs each recipe line in its own shell, so
a trap on its own line would not survive to the next. Begin with `set -e` and prefix the recipe
with `@` so its output is its own messages rather than a wall of echoed shell.

**Cleanup.** The recipe's first act after `set -e` is to allocate a log file with `mktemp` and
install `trap 'rm -f src/gate04_probe.mpconf src/gate05_probe.mpconf "$$log"' EXIT`. The two
probe filenames are fixed rather than mktemp-generated: `protoconf compile` resolves entry
points relative to `src/`, so the copies must live there, and a fixed name keeps the trap and
the compile argument in agreement.

**Per gate, in this order, twice — once for FOUND-04, once for FOUND-05:**

1. Build the mutated copy: `sed '<expression>' src/handshake_test.mpconf > src/<probe>.mpconf`.
   Redirect into a NEW file. Do not use `sed -i` on the tracked fixture, and do not back it up
   and restore it — the tracked file is never the file being mutated, which is what makes an
   interrupted run harmless. This deliberately diverges from the sketch in 01-REVIEW.md CR-02,
   which mutates `src/handshake_test.mpconf` in place and restores from `/tmp`; that shape
   leaves the tracked fixture modified if the compile is interrupted between the two steps.
2. Confirm the substitution landed: the `grep -q` from the matrix, against the copy. On failure,
   print `gates: FOUND-04 substitution did not land in src/gate04_probe.mpconf — check that
   test/src/handshake_test.mpconf:64 still reads exactly 'NEAR_BACKEND = BACKEND' on its own
   line` (and the FOUND-05 analogue, naming line 70 and `FAR_BACKEND = BACKEND`), then `exit 1`.
   This step is not optional and not reorderable: without it, a fixture edit that breaks the
   anchor produces a copy identical to the original, which compiles cleanly, which reads exactly
   like a gate that stopped firing.
3. Compile the copy, capturing both streams into the log, and neutralize the status:
   `protoconf compile . <probe>.mpconf > "$$log" 2>&1 || true`. The `|| true` here is on the
   COMPILE, whose non-zero exit is expected and is not the assertion — it is not an escape hatch
   on a check. Do not put `|| true` on any grep below.
4. Assert the gate's own message: the `grep -q '<message substring>' "$$log"` from the matrix.
5. Assert which gate fired: the `grep -q '<traceback substring>' "$$log"` from the matrix. This
   second assertion is what distinguishes "the gate fired" from "some fail() happened to print a
   similar phrase" — the traceback names the function.
6. On failure of either assertion, print `gates: FOUND-04 gate did not fire —
   _check_remote_backends did not report a local backend` (and the FOUND-05 analogue, naming
   `_check_reads_are_produced` and the unproduced state), then `cat "$$log"` so the maintainer
   sees what the compiler actually said, then `exit 1`.

**Success line.** End the recipe with `echo "gates: both compile gates fired"`. A target whose
recipe silently becomes empty exits 0; a target that has to print a specific line does not.

**Wire it into `test`.** Add `$(MAKE) gates` as the LAST line of the `test` recipe, after
`$(MAKE) workflows`. Last, not first: a contributor running `make test` should get their
